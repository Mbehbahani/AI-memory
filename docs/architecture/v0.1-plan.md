## A. Executive Summary

V0.1 is a single-machine, Docker-Compose, CPU-only, privacy-first memory infrastructure with eight
containers: PostgreSQL+pgvector, Neo4j, Ollama (Qwen3 4B), an embedding service (MiniLM-L6-v2, 384-d),
an ingestion service, a Memory Gateway API, an MCP server, and NeoDash for visualization (Neo4j Browser
comes bundled). No MinIO — the one MIRROR use case is served by a Postgres `bytea` blob table.

Three design decisions shape everything else:

1. **PostgreSQL is the system of record; Neo4j is a rebuildable projection.** Every entity, fact,
   artifact, and provenance row lives in Postgres first and is projected into Neo4j. Backup is
   trivial (dump Postgres + config), Graphiti is replaceable, and "where did you learn this?" is a
   SQL join.
2. **Graphiti is gated, not assumed.** A measured compatibility gate runs early (Phase 4, before graph
   code is written). If Graphiti-core with Ollama+Qwen3+MiniLM passes pre-agreed thresholds, it
   becomes the extraction engine behind our `KnowledgeEngine` port. If not, a native temporal engine
   (our prompts, Ollama JSON-schema-constrained decoding, our ontology) takes that slot. Both write
   the same Postgres tables and Neo4j label conventions, so the Gateway and MCP never change.
   Expectation (stated, not assumed): on this CPU-only laptop Graphiti's 6–10 LLM calls per episode
   will likely fail the latency threshold; the gate decides.
3. **Ingestion is tiered so the laptop stays usable.** Tier 0 (deterministic registry from my-vault
   frontmatter/links, minutes), Tier 1 (chunk + embed everything, minutes), Tier 2 (LLM extraction,
   hours, background, prioritized by note value). The system is queryable after Tier 1.

Recommended pilot project: **JobLab Lakehouse (DE)** at `D:\AWS2\SupaBaseProject\DE` — active, mixed
docs/code/data, explicit decision records (`docs/04-source-automation-decision.md`,
`06-platform-architecture-decision.md`), and real IGNORE needs (bundled JDK, `tools-cache/`).

Hardest constraint: **no CUDA GPU** (Intel Iris Xe only; not passable through Docker Desktop/WSL2).
Qwen3 4B runs on 4 cores. Full-vault LLM extraction is ESTIMATED 6–12 hours of background work;
embedding the vault is ESTIMATED under 2 minutes. Phase 4 measures both.

## G. PostgreSQL Data Model

Extensions: `vector`, `pg_trgm`, `pgcrypto`. Alembic migrations. Ids `uuid`, timestamps `timestamptz`.
[PROV] marks the provenance column set.

Registries: `devices`, `projects` (slug id, track, parent, status, goal_ids, attributes), `project_aliases`,
`source_roots`, `embedding_models`, `extraction_models`.

Sources & content: `sources` (uri unique, root, relative_path, project, kind, media_type, policy, status
active/deleted/moved, moved_from, current_version, secret_suspected), `source_versions` (content_hash,
size, mtime, git_commit, observed_at, run, is_current; unique (source_id, content_hash)), `source_text`

text_hash, heading_path, offsets, token_count, tsvector), `embeddings` (polymorphic object_type/id,

Episodes & knowledge: `episodes` (type, source/version/project, title, section_path, occurred_at,
observed_at, status, attempts, engine, graph_episode_uuid, origin, origin_client), `entities`
(type, canonical/normalized name, aliases, project, summary, merged_into; trigram index),
`entity_mentions` [PROV], `facts` (subject, predicate, object, text, valid_from/to, observed_at,
invalidated_at/by, supersedes, confidence, status current/historical/unconfirmed) [PROV],
`knowledge_artifacts` (type, title, body, structured, project, current_status, valid_from/to,
supersedes/superseded_by, confidence) [PROV], `artifact_entities`.

Operations & audit: `ingestion_runs`, `ingestion_jobs` (per (version, stage) state machine),
`source_events` (append-only), `retrieval_logs`, `mcp_audit_log`, `alembic_version`.
View `provenance_v` joins any id to source_uri, hash, version time, project, device, models, run.

Rule: if you need to read the text, it is Postgres; if you need to walk it, it is Neo4j.

## H. Neo4j Ontology

Defined in `schemas/ontology.yaml` (18 labels, 19 relationship types, functional predicates).
Two population layers: a structural graph built deterministically from registries and document
structure (always available after Tier 0/1) and an LLM-extracted graph (Tier 2), engine-agnostic.
All nodes carry `id` (= Postgres id), `name`, `type`, `project_id`, `summary`, `status`,
`valid_from`, `valid_to`, `observed_at`, `source_id`, `episode_id`, `confidence`, `engine`.

## I. Temporal Memory Model

1. Functional predicates: a new fact with the same subject+predicate and a different object closes the
   old one (`valid_to = new.valid_from`, `status=historical`) and links `SUPERSEDES`. Non-functional
   predicates accumulate.
2. Explicit supersession in text or via `record_decision(supersedes=…)` is authoritative.
3. Source edits do not delete knowledge: facts from an old version not re-extracted from the new one
   become `unconfirmed` (still current, ranked lower, flagged). Only contradictions or user actions close them.
4. Source deletion marks derived facts `source_status=deleted`; nothing is erased.
5. Point-in-time: `valid_from <= as_of AND (valid_to IS NULL OR valid_to > as_of)`.
6. Artifact kinds and statuses are explicit (see ontology); "superseded decision" is a state, not a deletion.

## J. Provenance Model

Every derived row: `source_id, source_uri, source_hash, source_version, project_id, device_id,
observed_at, valid_from, valid_to, confidence, extraction_model_id, embedding_model_id,
ingestion_run_id, episode_id` (+ heading_path/offsets for chunks). `Gateway.explain(id)` returns the
chain artifact/fact → episode → version → source → root/device + models + run. Registry-derived facts
carry `extraction_model_id = deterministic:registry-v1`.

## K. Source Storage Policies

Resolution: built-in deny list → `.memoryignore` → `config/policies.yaml` → per-root override →
secret-detector downgrade. IGNORE (dependency/build/cache trees, lockfiles, binaries, LaTeX artifacts,
vault internals), CATALOG_ONLY (datasets, archives, media, model files, > 2 MB, Excalidraw, anything
flagged), INDEX_CONTENT (md, txt, code, sql, tex, yaml/toml/json < 200 KB, pdf, docx, ipynb), MIRROR
(opt-in per root: `AIOS/me.md`, `AIOS/Maps/project-graph.md`). Secret detector patterns are in
`config/policies.yaml`; a match means metadata only, no text stored, nothing logged.

## L. Ingestion Architecture

Resumable state machine per (source_version, stage) in `ingestion_jobs`:
discover → classify → fingerprint → diff {new|modified|moved|deleted|unchanged} → extract metadata →
extract text → chunk → embed (batched) → episodes (Tier 2 queue) → extract knowledge → validate →
resolve entities → temporal rules → Postgres → Neo4j projection → provenance complete.

| Case | Detection | Action |
|---|---|---|
| unchanged | same hash, same URI | touch `last_seen_at`; no reprocessing |
| modified | same URI, new hash | new version; re-chunk; embeddings reused by text_hash; `document_change` episode; old facts `unconfirmed` |
| moved/renamed | hash seen at A (missing) appears at B | same `source_id`, URI updated, event recorded; no re-extraction |
| deleted | URI missing after full root scan | `status=deleted`; knowledge kept, flagged |
| duplicate | same hash at two URIs | text/chunks once per hash; episodes once; both sources linked |
| extraction failure | invalid JSON after retries / timeout | episode `failed`, error kept, vectors intact; `reprocess --failed` |
| interruption | process killed | stale `running` jobs re-queued; writes idempotent on (version, stage) |

Concurrency: embed batches 32 × 2 workers; LLM strictly serial. Scans are manual/scheduled.
Tiering: Tier 0 registry → Tier 1 embed all → Tier 2 LLM by priority (AIOS, Projects, Areas, decision
docs, READMEs first; clippings last).

## M. Qwen3 4B Integration

`LLMProvider` port; `OllamaProvider` uses `/api/chat` with `format=<JSON schema>`, `think=false`,
`temperature 0`, `num_ctx 8192`, `num_predict 1024`, timeouts, retry with error feedback (max 2).
Model identity (`qwen3:4b` + digest) stored in `extraction_models` and stamped on every artifact.
Native engine: 2–3 calls per episode (`schemas/extraction/*.json`). Swapping the provider or model is
configuration only. No cloud model is ever substituted silently; if Qwen3 4B is insufficient, evidence
is recorded, alternatives proposed, and development stops at that decision.

## N. MiniLM Embedding Architecture

FastAPI + sentence-transformers `all-MiniLM-L6-v2` (384-d, max_seq 256 → chunks ≈ 200 tokens),
normalized, CPU torch (2 threads). `POST /embed`, `POST /v1/embeddings` (OpenAI-compatible),
`GET /health`. Model baked at image build; `HF_HUB_OFFLINE=1` at runtime. `embedding_models` stores
name/dimension/revision/normalization; model change is additive. HF text-embeddings-inference is a
documented drop-in alternative behind the same contract.

## O. Graphiti Compatibility Strategy

Graphiti is used only as `graphiti-core` behind the `KnowledgeEngine` port
(`process_episode(episode, context) -> ExtractionResult`; `invalidate(fact_id, at, by_episode)`).
With the Graphiti engine, `add_episode()` results are mirrored into Postgres so Postgres remains the
system of record and Neo4j stays rebuildable.

Gate (P4, ~1 h machine time): graphiti-core → `OpenAIGenericClient(base_url=ollama/v1, model=qwen3:4b)`
+ `OpenAIEmbedder(base_url=embedding-service, dim=384)` + Neo4j; 10 real my-vault episodes + the
Architecture-A/B supersession fixture; 2 concurrent for one pair.

| Criterion | Threshold |
|---|---|
| C1 schema reliability | ≥ 90 % of Graphiti LLM calls parse after its retries; 0 unhandled exceptions |
| C2 latency | median ≤ 240 s per ~800-token episode, p90 ≤ 480 s |
| C3 quality | ≥ 60 % expected entities and ≥ 50 % expected relationships (hand-listed per episode) |
| C4 temporal | supersession fixture: old edge invalidated, new edge current |
| C5 concurrency | 2 parallel episodes complete without deadlock/corruption |
| C6 storage | 384-d vectors stored; indices/constraints created |

Decision rule (automatic): all pass → Graphiti engine; any fail → native engine. Verdict recorded in
`reports/graphiti-gate.md` and an ADR. The full native extraction path is built only if the gate fails.

## P. Hybrid Retrieval

1. Semantic candidates: query embedding → pgvector HNSW top-40 over chunks + artifacts, SQL-filtered by
   project, policy, source status, `since`.
2. Keyword candidates: tsvector top-40. Fused by Reciprocal Rank Fusion (k=60).
3. Graph expansion: entities mentioned by top-15 fused hits → Neo4j 1-hop (≤ 25 nodes).
4. Temporal filter (`as_of`). 5. Provenance attachment. 6. Context assembly (ordered blocks, 6k-token budget).
Score = RRF + boosts (project +0.1, entity-linked +0.1, recency decay, unconfirmed −0.15); weights in
`config/retrieval.yaml`; every query logged in `retrieval_logs`.

## AF. Ongoing Evaluation Protocol (added 2026-09-14, ADR-0010)

The one-time checks (P4 Qwen3 measurements, the Graphiti gate, the P14 gold-set run) answer "does it
work at build time". This protocol answers "is it still working, and is Qwen3 4B good enough" during
day-to-day use, and defines when a better model is justified.

**How the memory updates itself.** There is no live watcher. An update is a scan run
(`scripts/ingest` → `aimemory-ingest run`): every file under the allowed roots is hashed; unchanged
files are skipped; changed/new files are re-chunked and re-embedded (seconds, no LLM); their episodes
are queued for Qwen3 extraction (minutes per document, serial, background); temporal rules update the
graph. Qwen3 4B is used only in the extraction step. Runs are started on demand (end of a work session)
— a scheduled task is documented but not installed (AC-10).

**Measured continuously (no human effort):** written to `metrics_snapshots` after every ingestion run
and every `scripts/eval` run, shown on a NeoDash "Health" page and in `aimemory-ingest status`:

| Metric | Source | Watch for |
|---|---|---|
| JSON-schema validity rate of LLM calls | `episodes.attempts`, provider logs | < 85 % over a run |
| Failed-episode share | `episodes.status` | > 10 % |
| Median seconds per episode | `ingestion_jobs` timings | drift upward |
| Entity duplicate rate (same normalized name, different ids, same type) | SQL check | growth |
| Unconfirmed-fact share | `facts.status` | growth without review |
| Coverage per project (episodes extracted / INDEX_CONTENT sources) | `status` | stalls |
| Gold-set hit@5, expected-entity presence, provenance completeness | `scripts/eval` | regression vs previous snapshot |

**Human review (≈ 15 minutes, weekly or after a big ingest):** `aimemory-ingest review --sample 20`
prints 20 random recent artifacts/facts with their evidence quote and source citation; the owner marks
each `accept | wrong | partial` (CLI or NeoDash form → `extraction_reviews` table). Acceptance rate is
the primary quality number for the extraction model.

**Permanent benchmark set:** the gate episodes (10 real my-vault episodes + the A/B fixture) with
hand-listed expected entities/facts are kept in `tests/evaluation/benchmark/` and never changed, so any
model can be compared on identical input: `scripts/eval --benchmark --model <name>` writes
`reports/benchmark-<model>-<ts>.md` (validity, entity/fact recall, seconds per episode, RAM).

**Model-upgrade rule (no silent switch, ADR-0010):** if acceptance rate < 70 % over two consecutive
reviews, or validity < 85 % over two runs, the owner is told, and the candidate (e.g. `qwen3:8b`, ~5 GB
RAM, roughly 2× slower — ESTIMATED) is run on the benchmark set only. The switch happens only if the
owner approves after seeing the two benchmark reports side by side; `LLM_MODEL` is the single change,
and `extraction_models` records both models so provenance shows which model produced each fact.

## AG. Ops Dashboard and Ingestion Worker (added 2026-09-14, ADR-0011)

A built-in, offline operator page at `http://127.0.0.1:8000/ops` (served by memory-api; HTML + HTMX,
no new container) replaces the CLI as the day-to-day surface: Health · Runs (with **Run scan / Retry
failed / Run eval / Run benchmark** buttons) · Coverage per project · Quality trends (the §AF metrics)
· Review queue (the weekly 20-sample review as a form) · Attention list (unconfirmed facts, suspected
secrets, deleted sources, model-upgrade notice). NeoDash remains the graph-exploration tool.

To make the buttons work without giving any container Docker control, the ingestion service runs as an
always-on **worker** (`aimemory-ingest worker`, idle ≈ 0.2 GB ESTIMATED) polling a `run_requests`
table; the page and the CLI both enqueue requests. Remote (online) access is out of scope for V0.1:
it would need authentication and TLS and belongs with the multi-device boundary.

Compose change: `ingestion` loses the `ingest` profile and becomes `restart: unless-stopped` with
`command: ["aimemory-ingest", "worker"]`; one-off CLI use stays available via `docker compose exec ingestion …`.
