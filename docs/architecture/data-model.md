# Data Model — PostgreSQL (V0.1)

Status: **implementable spec**, frozen with the P1 contract · Author: A02 · Date: 2026-09-14
Source of truth in code: `packages/aimemory/domain/models.py` · Consumer: **A04** (P5-T01, Alembic
migration `0001_initial` + `0002_ops_eval`), then A07a/A08/A09/A16.

PostgreSQL is the system of record (ADR-0001). Neo4j holds nothing that is not here first.
Everything below is derived from plan section G with the exact types, constraints and indexes A04
must create. Where the plan named a concept but not a column, this document fixes it; those places
are listed under [Deviations](#deviations).

## 0. Conventions

| Rule | Value |
|---|---|
| Extensions | `vector`, `pg_trgm`, `pgcrypto` (created in `infra/postgres/init/01-extensions.sql`) |
| Surrogate keys | `uuid PRIMARY KEY`, generated by the application (`aimemory.common.ids.new_id`, UUIDv7 layout — time-ordered, so index inserts stay local). **No** `gen_random_uuid()` defaults, because the application needs the id before the insert. |
| Registry keys | `text PRIMARY KEY` slugs (`projects.id`, `devices.id`, `source_roots.root_id`, `embedding_models.id`, `extraction_models.id`) |
| Timestamps | `timestamptz`, always UTC. `created_at timestamptz NOT NULL DEFAULT now()` where present. |
| Enums | stored as `text` with a `CHECK (col IN (...))` constraint generated from the matching `StrEnum` in `aimemory.domain.enums`. **Not** native `CREATE TYPE` enums: adding a value later must not require `ALTER TYPE` in a migration lock. |
| JSON | `jsonb` (`attributes`, `structured`, `counters`, `params`, `details`, `frontmatter`, `arguments`) |
| Arrays | `text[]` for short homogeneous lists (`aliases`, `goal_ids`, `heading_path`, `links`, `section_path`) |
| Vectors | `vector(384)`; the dimension is `EMBED_DIMENSIONS` and is asserted against `embedding_models.dimension` at startup |
| Deletion | **Nothing is hard-deleted.** Rows get a status; `source_events` keeps the history (ADR-0005 rules 3–4). |
| Naming | tables plural snake_case; indexes `ix_<table>_<cols>`; uniques `uq_<table>_<cols>`; checks `ck_<table>_<what>`; FKs `fk_<table>_<ref>` |
| FK policy | `ON DELETE RESTRICT` everywhere except `source_text`, `mirror_blobs`, `chunks`, `embeddings` → `ON DELETE CASCADE` from their version/object, because those are re-derivable |

Migration split:

* `0001_initial` — everything in sections 1–4 plus the seeds and the `provenance_v` view.
* `0002_ops_eval` — section 5 (ADR-0010 / ADR-0011 tables), created in P12-T02 / P14-T05.

`status text NOT NULL DEFAULT 'queued' CHECK IN ('queued','running','done','failed','cancelled')` ·
`progress_pct int NOT NULL DEFAULT 0 CHECK (progress_pct BETWEEN 0 AND 100)` · `message text` ·
`started_at`, `finished_at timestamptz` · `run_id uuid NULL REFERENCES ingestion_runs(id)` · `error text`.
Index: `ix_run_requests_queue (status, requested_at) WHERE status IN ('queued','running')`.
Worker claim is `UPDATE ... SET status='running' WHERE id = (SELECT id ... FOR UPDATE SKIP LOCKED)`.

### `service_stats` (ADR-0011)
`id uuid PK` · `at timestamptz NOT NULL DEFAULT now()` · `service text NOT NULL` ·
`process_rss_bytes bigint` · `model_loaded boolean` · `model_name text` ·
`details jsonb NOT NULL DEFAULT '{}'`.
Index: `ix_service_stats_at (service, at DESC)`.
Container RAM from `docker stats` is **not** available inside containers; these values are
self-reported process RSS and Ollama `/api/ps` state, and the Ops page labels them as such.

## 6. The `[PROV]` column set (plan section J)

These 14 columns appear, with these names and types, on `entity_mentions`, `facts` and
`knowledge_artifacts`. `packages/aimemory/domain/provenance.py: PROVENANCE_COLUMNS` is the same list
in the same order and `tests/unit/test_contracts.py` asserts it.

| Column | Type | Notes |
|---|---|---|
| `source_id` | `uuid NULL REFERENCES sources(id)` | NULL only for manual/MCP-origin rows |
| `source_uri` | `text` | denormalized so provenance survives a root rename |
| `source_hash` | `text` | `sha256:<hex>` of the version |
| `source_version` | `uuid NULL REFERENCES source_versions(id)` | *the version id*; the plan's name is kept |
| `project_id` | `text NULL REFERENCES projects(id)` | |
| `device_id` | `text NOT NULL REFERENCES devices(id)` | |
| `observed_at` | `timestamptz NOT NULL` | |
| `valid_from` | `timestamptz` | mirrors the row's own window |
| `valid_to` | `timestamptz` | |
| `confidence` | `real NOT NULL DEFAULT 1.0` | |
| `extraction_model_id` | `text NULL REFERENCES extraction_models(id)` | `deterministic:registry-v1` for Tier 0 |
| `embedding_model_id` | `text NULL REFERENCES embedding_models(id)` | |
| `ingestion_run_id` | `uuid NULL REFERENCES ingestion_runs(id)` | |
| `episode_id` | `uuid NULL REFERENCES episodes(id)` | |

Chunk-scoped extras, present on `entity_mentions` only (chunks carry their own):
`heading_path text[]`, `char_start int`, `char_end int`.

Columns are declared **once per table**: where a table already owns a column of the same name, that
column *is* the provenance column. Concretely, `facts` and `knowledge_artifacts` own
`valid_from`/`valid_to`/`observed_at`/`confidence`/`project_id`, and `entity_mentions` owns
`episode_id`/`confidence`. A04 must not create duplicates.

### View `provenance_v`

One row per derived object, so `Gateway.explain(id)` is a single select:

```sql
CREATE VIEW provenance_v AS
SELECT 'fact'::text AS object_type, f.id AS object_id, f.project_id, f.episode_id,
       f.source_id, f.source_uri, f.source_hash, f.source_version, f.device_id,
       f.observed_at, f.valid_from, f.valid_to, f.confidence,
       f.extraction_model_id, f.embedding_model_id, f.ingestion_run_id,
       s.uri AS current_source_uri, s.status AS source_status, sr.root_id, sr.label AS root_label,
       em.name AS extraction_model_name, em.digest AS extraction_model_digest,
       bm.name AS embedding_model_name, r.started_at AS run_started_at
FROM facts f
LEFT JOIN sources s            ON s.id  = f.source_id
LEFT JOIN source_roots sr      ON sr.root_id = s.root_id
LEFT JOIN extraction_models em ON em.id = f.extraction_model_id
LEFT JOIN embedding_models bm  ON bm.id = f.embedding_model_id
LEFT JOIN ingestion_runs r     ON r.id  = f.ingestion_run_id
UNION ALL
SELECT 'artifact', a.id, a.project_id, a.episode_id, ...   -- same shape from knowledge_artifacts
UNION ALL
SELECT 'entity_mention', m.id, ...                          -- same shape from entity_mentions
;
```

## 7. Repository layer (A04)

`packages/aimemory/persistence/` exposes one repository per aggregate, each returning the pydantic
models of `aimemory.domain.models` — never raw rows and never ORM objects:
`ProjectRepo`, `SourceRepo` (`upsert_source`, `record_version`, `mark_moved`, `mark_deleted`),
`ChunkRepo`, `EmbeddingRepo` (`get_by_hash`, `bulk_insert`), `EpisodeRepo` (`claim_next`,
`mark_extracted`, `mark_failed`), `EntityRepo`, `FactRepo` (`close_fact`, `insert_superseding`),
`ArtifactRepo`, `RunRepo`, `JobRepo` (`upsert(version_id, stage, state)`), `AuditRepo`, `MetricsRepo`.

Idempotency rules A04 must implement:

1. `INSERT ... ON CONFLICT (version_id, stage) DO UPDATE` for jobs.
2. `INSERT ... ON CONFLICT (source_id, content_hash) DO NOTHING RETURNING id` for versions.
3. `INSERT ... ON CONFLICT (text_hash, model_id) DO NOTHING` for embeddings.
4. Deterministic ids (`aimemory.common.ids.deterministic_id`) for chunks and structural entities, so a
   replayed stage writes the same rows.

## Deviations

Differences from `v0.1-plan.md`, all additive and none reversing an ADR:

1. **Enums as `text` + `CHECK`, not native Postgres enums.** The plan says "enums"; native types make
   later value additions a locking migration. The `CHECK` lists are generated from the `StrEnum`s.
2. **`source_versions.change_type` added.** The plan names the five change cases (section L) but stores
   them nowhere; recording the case on the version makes the memory-scenario tests (P6-T04) assertable.
3. **`sources.policy_reason`, `sources.origin`, `sources.trust` added.** Required by AC-6 (Clippings →
   `external`/`low`) and by "flagged files never stored" auditing (plan section T).
4. **`episodes.tier`, `episodes.priority`, `episodes.body` added.** ADR-0006 needs a persisted queue
   order; the plan mentions priority only in prose.
5. **`uq_facts_functional_current` partial unique index added.** ADR-0005 rule 1 was specified as
   engine behaviour only; enforcing it in the database makes a temporal bug impossible to persist.
6. **`uq_entities_type_normalized_project` added.** ADR-0010 tracks a "duplicate entity rate"; the
   index makes exact duplicates unrepresentable, leaving only near-duplicates to measure.
7. **`chunks.tsv` is a stored generated column** rather than a trigger-maintained one.
8. **`mirror_blobs` uses `version_id` as its primary key** (one blob per version), not a surrogate id.
9. **`SubProject` is not a separate table or label** — it is `projects.parent_id` (and `:Project` with
   `parent_id` in Neo4j). See `ontology.md`.
10. **`retrieval_logs."limit"` is a quoted identifier** (`limit` is reserved). The domain field is
    `SearchQuery.limit` with alias `k` for MCP compatibility.
